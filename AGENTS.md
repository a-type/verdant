# AGENTS.md

Guidance for AI agents and contributors working in the Verdant monorepo.

Verdant is a persistence, sync, and collaboration framework for local-first web apps. It is a pnpm workspace + Turborepo monorepo. Every package lives in `packages/*`; end-user behavior is specified by the integration test suite in `test/`.

## Environment & Tooling

- **Package manager:** pnpm (root declares `packageManager: pnpm@10.34.4`; `mise.toml` pins node 24 / pnpm 10). Use pnpm, never npm/yarn.
- **Node version:** 24 (CI + mise). A Volta pin (`volta.node`) is also present.
- **Task runner:** Turborepo (`turbo.json`). Tasks shared across the repo: `build`, `dev`, `test`, `ci:test:unit`, `ci:test:integration`, `typecheck`, `gen`, `preview`, `link`.
- **TypeScript:** strict, `module`/`moduleResolution` = `NodeNext`. Source imports must use explicit `.js` extensions (ESM). Root tsconfig sets `customConditions: ["development"]`.
- **Formatting:** Prettier only (`.prettierrc`): tabs, `tabWidth: 2`, single quotes, trailing commas. There is no ESLint config — Prettier + `typecheck` are the quality gates.
- **Shared dependency versions:** cross-package dev/peer deps (react, typescript, vite, vitest, playwright, hono, kysely, better-sqlite3, etc.) are pinned in the `catalog:` in `pnpm-workspace.yaml`. Prefer catalog entries over ad-hoc versions.

## Key Commands

Run from the repo root:

- `pnpm i` — install all workspace dependencies.
- `pnpm test` — unit tests then integration tests (turbo pipeline).
- `pnpm test:integration` — integration suite only (`pnpm -F @verdant-web/test test`).
- `pnpm test:watch` — run `test` tasks in watch mode.
- `pnpm build` — build all packages.
- `pnpm typecheck` — `tsc --noEmit` across packages.
- `pnpm benchmark` — run the scale test in `test/`.
- `pnpm changeset` — add a changeset for a release (required for any published-package change).
- `pnpm ci:playwright:install` — install Playwright browsers (needed before integration tests on a fresh machine).

You can scope to a single workspace: `pnpm -F @verdant-web/store test`, `pnpm --filter @verdant-web/cli typecheck`, etc. `pnpm -F <pkg> <script>` runs that package's script directly.

## Repository Layout

- `packages/*` — publishable npm packages (`@verdant-web/*`):
  - `store` — client DB, reactive queries, files, undo, sync client.
  - `server` — sync/presence server (Hono-based), storage adapters.
  - `common` — shared utilities & types used by both client and server.
  - `cli` — schema → typed client code generator + migration bootstrapping.
  - `react` — React bindings.
  - `cloudflare` — Cloudflare Workers/Durable Objects server adapter.
  - `file-storage-s3`, `persistence-sqlite`, `persistence-capacitor-sqlite` — storage/persistence adapters.
  - `create-app` — project scaffolding (contains `templates/`).
  - `tiptap` — TipTap editor integration.
- `test/` — the `@verdant-web/test` integration suite (see below). This is the **source of truth for end-user behavior**; when fixing a bug or adding a feature, add a high-level test here.
- `docs/` — Docusaurus site (content in `docs/docs/*.md`, sidebar is autogenerated).
- `examples/` — runnable example apps (`vanilla`, `cloudflare`).
- `scratchpad/` — personal playground for testing the libraries against a real app; its `src/` is gitignored, don't commit anything there.
- `configs/` — shared config workspace.
- `test/servers/` — the node & cloudflare test server implementations used by integration tests.

## Package Conventions

Every published package follows the same shape (see `packages/store/package.json`):

- `"type": "module"`, ESM build output in `dist/esm/`.
- `exports` map includes a `development` condition pointing at `./src/index.ts` so workspace imports resolve to **source directly** (no build needed for dev/tests). `publishConfig.exports` strips the development condition and points to `dist/`.
- `"files": ["dist/", "src/"]`.
- Standard scripts: `build` (`tsc -p tsconfig.json`), `test` (vitest), `ci:test:unit` (`vitest run`), `typecheck` (`tsc --noEmit`), `prepublish` (build), `link`.
- Cross-package deps use `"workspace:*"` (e.g. `@verdant-web/common: "workspace:*"`).
- Shared deps come from the catalog (e.g. `"typescript": "catalog:"`).
- Packages are versioned independently via changesets; a change to `common` used by `store` will bump both.

## Code Style

- Tabs for indentation, single quotes, trailing commas. Format with Prettier.
- ESM with NodeNext: use `.js` in relative import specifiers (e.g. `import { Client } from './client/Client.js'`).
- Type exports: use `export type` for types, `export *` sparingly for value+type modules. Public API surface is curated in each package's `src/index.ts`.
- Keep packages focused: shared logic goes in `@verdant-web/common`; client-only in `store`; server-only in `server`.
- Do not add code comments unless they add real value (e.g. explaining why a tricky invariant holds).

## Testing

- **Unit tests:** per-package vitest suites (e.g. `packages/store/src/__tests__/*.test.ts`, `packages/cli`, `packages/react`, `packages/server`). Run with `pnpm -F <pkg> test`.
- **Integration tests** (`test/tests/*.test.ts`) run in a **browser** (vitest browser mode + Playwright chromium) against real in-repo server processes. They cover sync, conflict resolution, fuzzing, migrations, presence, files, undo, auth, pruning, etc.
  - The client used in tests is **generated** from `test/schema.ts` by the CLI. `test/`'s `pretest` script regenerates it: `tsx ../packages/cli/src/bin/index.ts -s ./schema.ts -o ./client ...`. Run this after schema changes.
  - Two server backends are exercised via vitest projects: `hono` (Node) and `cf` (Cloudflare Workers). A third variant runs with `SQLITE=true` for sqlite persistence.
  - Tests build clients through `createTestContext`/`createTestClient` in `test/lib/` and use `waitFor*` helpers (`test/lib/waits.ts`) to await sync convergence. Prefer these helpers over raw `setTimeout`.
  - `test/lib/createTestContext.ts` auto-registers `afterAll` cleanup; don't leak clients.
- `test/benchmark.ts` + `test/longevity.ts` are the scale/longevity suites (`pnpm benchmark`).

## Releases (Changesets)

- Every change to a published package requires a changeset: `pnpm changeset` (minor/patch; this repo uses standard semver, no prerelease workflow currently active).
- CI (`changesets.yaml`, on push to `main`) runs `pnpm ci:version` then `pnpm ci:publish` with `--access=public`. Changelogs are auto-generated — don't hand-edit `CHANGELOG.md`.
- `baseBranch` is `main`. The `version` script and publishing are CI-owned; agents should only add changesets, not run `ci:version`/`ci:publish` manually.

## Documentation

- Docs live in `docs/docs/` as Markdown/MDX; the sidebar is autogenerated from the folder structure (`docs/sidebars.js`), so no sidebar edits are needed for new pages.
- Preview locally: `pnpm --filter docs start`; build with `pnpm --filter docs build-docs`. Deployed to GitHub Pages from `main` via `docs.yaml`.
- Keep docs consistent with actual package exports and the integration tests.

## CI

- `tests.yaml` (PRs to `main`): install with `--frozen-lockfile`, install Playwright, `pnpm build`, `pnpm ci:test:unit`, `pnpm ci:test:integration`.
- `changesets.yaml` and `docs.yaml` run on push to `main`.
- Don't commit generated artifacts beyond what's already tracked (`test/client` is generated/committed; `test/.client-sqlite`, scratchpad `src/`, and `dist/` are ignored).
